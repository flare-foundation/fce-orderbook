# Getting started — local

Get the orderbook running on a local devnet and place a trade. For a deployed
Coston2 extension see [deployment-steps.md](deployment-steps.md).

## Prerequisites

| Need | Why |
|---|---|
| Docker + Compose | runs the extension TEE, proxy and redis |
| Go 1.25+ | `tools/` CLIs |
| Foundry (`forge`, `cast`) | compiles contracts, reads chain state |
| Node 20+ | frontend and `xaman-service` |
| A funded key | deploys contracts and registers the extension |
| FCC infrastructure running | Hardhat node + indexer + redis + the "normal" TEE proxy. Not in this repo — see `../../e2e/` |
| `tee-node` + `tee-proxy` cloned as siblings | `go.mod` uses `replace … => ../../tee-node`; the proxy image is built from source |

## One command

```bash
cp .env.example .env          # fill in DEPLOYMENT_PRIVATE_KEY
./scripts/full-setup.sh
```

That chains: deploy contracts + register the extension (`pre-build.sh`) → deploy
test tokens (`extension-setup.sh`) → start TEE/proxy/redis (`start-services.sh`) →
register the TEE version and machine (`post-build.sh`) → bind the TEE signer
(`extension-post-setup.sh`).

Add `--test` to run the e2e suite afterwards, or `--chain coston2` to target the
testnet.

> ⚠️ Never run `full-setup.sh` against a **remote** TEE. It chains
> `extension-post-setup.sh`, which locks `setTeeAddress` to whatever key exists at
> that moment — one-shot, and wrong bindings cost a new InstructionSender. See
> [deployment-steps.md](deployment-steps.md).

## Frontend

```bash
cd frontend && npm install && npm run dev      # http://localhost:5173
```

`npm run dev` runs `sync-config` first, which regenerates
`src/config/generated.ts` from `config/extension.env`, `config/pairs.json` and the
forge artifacts. Re-run it after any redeploy or the UI drives the *previous*
deployment's contracts.

Leave `VITE_TEE_PROXY_URL` empty: the app then issues relative URLs that Vite
proxies same-origin, avoiding CORS (the proxy answers `OPTIONS` with 405).
Point it elsewhere with `VITE_PROXY_UPSTREAM` (default `http://localhost:6674`).

For the Xaman/XRPL wallet flows, also run:

```bash
cd xaman-service && npm i && npm start         # :8787
```

## Verify it works

```bash
curl http://localhost:6674/info                # 200 + teeInfo JSON
./scripts/test.sh                              # deposit → order → match → withdraw
```

In the UI: connect MetaMask → faucet a test token → deposit → place a bid and an
ask that cross → confirm the fill → withdraw.

## Configuration

Everything is env-driven; see `.env.example` for the full list.

| Var | Note |
|---|---|
| `DEPLOYMENT_PRIVATE_KEY` | funded deployer; the Hardhat dev key works on local devnet |
| `CHAIN_URL` / `CHAIN_ID` | `CHAIN_ID` is **required** — unset leaves `chainID=0` and every TEE signature comes back empty |
| `NETWORK` | which `config/<network>/pairs.json` gets baked into the image |
| `EXT_PROXY_URL` | this extension's proxy; must be publicly reachable on testnets |
| `SIMULATED_TEE` | `true` on a laptop, **`false`** on real Confidential hardware |

`config/extension.env` is generated by `pre-build.sh` — don't edit it by hand.

## Stopping

```bash
./scripts/stop-services.sh                     # add --chain coston2 to match
```

## Common failures

| Symptom | Cause |
|---|---|
| `Extension ID is not set.` | `extension-post-setup.sh` never completed |
| `token not allowed` | token missing from the vault allow-list |
| `'forbidden': invalid teeID` in proxy logs | TEE was restarted without restarting the proxy — the proxy latches one identity. Restart both together |
| `pollAction timeout` / `/action/result` 404 | more than one active TEE machine; instructions are load-balanced to a dead one. See [deployment-steps.md](deployment-steps.md) |
| `signature must be 65 bytes, got 0` | `CHAIN_ID` unset on the TEE |
